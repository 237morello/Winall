CONTEXTE
Projet Next.js 15 (App Router) + TypeScript + Tailwind, convention de composants à 4 fichiers déjà en place :
  ComponentName.types.ts
  ComponentName.constants.ts
  ComponentName.tsx
  index.ts
avec une classe statique `ComponentService` pour la logique (formatage, calculs, etc.), séparée du JSX.
Design system existant : variables CSS en OKLCH (--color-p vert, --color-o orange, --color-g neutre), style flat (pas de gradient, pas de shadow), font-weight 400/500 uniquement, bordures 0.5px, icônes Lucide/Tabler.

OBJECTIF
Créer une page admin "Système et ressources" à l'adresse /admin/systeme (ou équivalent selon la structure de routes existante). Cette page est réservée à l'admin et affiche l'usage/les quotas des services externes utilisés par Winall (Supabase, Upstash Redis, Vercel, Resend).

CONTRAINTES DE LAYOUT
- Pas de sidebar. Layout en page normale avec une nav horizontale en haut (logo + liens + avatar admin).
- Contenu centré, largeur max ~1100px.
- Titre de page + sous-titre, une ligne de 3 mini stat-cards, puis une grille de cartes (une par service) avec pour chaque carte : icône, nom, catégorie/plan, badge de statut (Actif / À surveiller), et des barres de progression par métrique (valeur actuelle / limite), colorées vert si sain, orange si >80% du quota.

STRUCTURE DE DONNÉES ATTENDUE
Créer un type `ExternalService` avec : id, nom, catégorie, plan, statut ('active' | 'warning' | 'critical'), et une liste de métriques `{ label, current, limit, unit }`.
`ComponentService` doit exposer une fonction pure qui calcule le pourcentage d'usage et détermine la couleur de la barre (seuils : <70% vert, 70-90% orange, >90% rouge) — pas de logique dans le JSX.

DONNÉES
Pour l'instant, utiliser un tableau de données statique (mock) dans .constants.ts pour Supabase, Upstash, Vercel, Resend. Ne PAS appeler les vraies APIs externes dans cette étape — juste la UI avec des données factices réalistes. On branchera les vraies APIs (Supabase Management API, Upstash REST API) dans une itération suivante via une route API Next.js séparée.

CODE
- Rester simple et court : pas de sur-ingénierie, pas d'abstraction inutile pour 4 services.
- Composants réutilisables : un `ServiceCard` qui prend un `ExternalService` en props, réutilisé pour les 4 cartes.
- Pas de librairie de composants externe (pas de shadcn, pas de Radix) sauf si déjà utilisée ailleurs dans le projet.

DÉPENDANCES
Si une dépendance npm est nécessaire (icônes, etc.), ne pas l'installer directement — lister ce qui est requis et me demander confirmation avant d'exécuter `pnpm add`.

LIVRABLE
Les fichiers du composant `SystemResourcesPage` (ou nom cohérent avec l'arborescence existante) suivant la convention 4 fichiers, plus la page route qui l'utilise.
